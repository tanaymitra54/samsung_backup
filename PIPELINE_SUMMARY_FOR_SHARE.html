PRISM Pipeline — Full Approach Summary

Quantum-inspired QUBO reasoning at inference + QLoRA SFT (our pipeline, not QUBO-for-dataset-curation)

1. Inference Pipeline (core approach — QUBO used at inference time)

  • Base model (training plan): Qwen/Qwen2.5-1.5B-Instruct → after SFT: checkpoints/prism-sft-v1/merged_model
  • Eval / fast configs also used: Qwen2.5-3B-Instruct, Llama-3.2-3B-Instruct (benchmark runs)
  • Candidate generation: 4 prompt perturbations × 4 samples = 16 reasoning chains / question
  • Temperature range: [0.3, 0.9] · top_p: 0.95 · max_new_tokens: 256
  • Verifier: Math = gold_match×0.6 + arithmetic_consistency×0.4 · Commonsense = NLI entailment (deberta-v3-base)
  • QUBO selection (Simulated Annealing): embed (MiniLM) → KMeans cluster (≤50) → ≤200 vars

2. SFT Dataset Generation (OpenMathInstruct stratified — not QUBO-curated chains)

  • Primary source: nvidia/OpenMathInstruct-2 (~600K) → stratified downsample → ~20,000 examples
  • High-signal add-on: 54 correct CoT traces from our benchmark CSVs (outputs/)
  • Total target: ~20,054 · format: Qwen chat template · path: training_data/combined_dataset/
  • Why this design: Improve base reasoning quality so PRISM sampler produces better candidates for QUBO

4. Preference Pair Generation & DPO (optional stage 2)

  • Chosen: correct CoT traces (correct_cot=1)
  • Rejected: incorrect CoT traces for same question
  • Available now from outputs/: 54 positive · 109 negative · 13 preference pairs (same-question overlap)
  • DPO defaults: β=0.1 · LR=1e-6 · epochs=2 · batch=4 · grad_accum=2 · LoRA r=16 α=32 · BF16/FP16 + 4-bit NF4
    • Scale-up path: collect more pos/neg pairs from full benchmark runs, or mine QUBO-selected vs low-score rejected chains.
